What Snips has

Read 2026-11-19 in C:\Users\sciss\IdeaProjects\Snips, package com.snips.formula: 21 files and 3,888 lines of Kotlin. About 2,300 of those lines are the general engine; the rest belongs to Snips' documents.

  • The language (Lexer.kt, the parser in Evaluator.kt, Cells.kt):
    • Numbers, strings with no escapes, TRUE and FALSE, and arrays written [1,2] or [[1,2],[3,4]].
    • References: A1, $A$1 and ranges A1:B5. Open ranges (A, A:C, A4:A) are filled in from the table's size. Lowercase hint forms (c5, r5, c1r1) also work.
    • Other tables and blocks are reached by dotted paths: T1.A1, M1.f(5), S1.fn().
    • Operators, loosest first: or, and, not; one comparison (= <> < > <= >=, also ≠ ≤ ≥); &; + -; * / % (% is modulo) and multiplication by juxtaposition (2x); unary signs; ^, right to left, so -2^2 is -4.
    • Not there: exponent notation inside a formula (1e3 reads as 1 times e3), LET, LAMBDA, and results that spill into neighbouring cells.
  • Values (Value.kt):
    • The kinds: a number (a double), text, a bool, an error with a detail, empty, a matrix, and two of Snips' own: Styled (a value with its look) and Rich (text with pictures).
    • The errors: #DIV/0! #REF! #NAME? #VALUE! #N/A #NUM! #CIRC! and four of Snips' own.
    • Dates are Excel's serial numbers.
    • Conversions are Excel's. Text compares without case. Numbers are equal within 1e-12 relative. Rounding goes half away from zero, and display shows 15 significant digits.
  • Calculation:
    • There is no dependency graph. Each change rebuilds the notebook and works out every cell again, on demand, keeping each result once worked out; bursts of edits are run together first.
    • A cycle gives #CIRC!. Every argument is worked out before a call, so IF evaluates both of its branches.
    • Matrices follow linear algebra: * is the matrix product.
  • Functions (Compute.kt): 91 names and 9 aliases. They cover maths, rounding, aggregates, statistics, logic, text, lookups (VLOOKUP XLOOKUP MATCH INDEX), conditional sums, dates and matrices. Snips adds 6 more for its feature trackers. The engine has no financial or engineering functions, no SUMIFS, and no INDIRECT. A reference of every function (help/FormulaReference.kt) feeds autocomplete and the hover cards.
  • Moving references (RefRewriter.kt, 221 lines): references are rewritten for fill, paste, move, and inserting or deleting rows and columns.
  • Tests: 208 for the engine and about 100 more around it.

The design

import Formula

val book = Workbook()
val sheet = book.sheet("Stats")
sheet["A1"] = 10
sheet["A2"] = 32
sheet["A3"] = "=SUM(A1:A2) * 2"
print(sheet.value("A3"))              // 84
sheet["A1"] = 20                     // A3 is marked; read again, it is 104
print(Formula.evaluate("ROUND(PI() * 2, 3)"))   // 6.283

// A program's own function, and references of its own (Snips' T1.A1, M1.f(5)).
book.functions.add("DAMAGE", 2) { args -> args[0].number * (1.0 - args[1].number) }
book.resolver = MyBlocks()            // an interface: what T1, M1, S1 are
  • Written in WinterWolf ("Jade first"), carried inside ww.exe as Jade is, and left out of built programs that do not import it.
  • Formulas are parsed once into a tree, kept with their cell, and evaluated by walking it. The tree also records the cells it reads, and that gives the dependency graph.
  • FormulaValue is a sealed set: number, text, bool, error (a code and a detail), empty, matrix, and Other(any). Other carries a host's own values (Snips' Styled and Rich) through formulas untouched. Functions that do not know such a value give #VALUE!.
  • The function table is open: the library's functions come first, and a program adds or replaces functions by name. Each function has a reference entry (its arguments, a line describing it, an example), which a program can list for autocomplete and help.
  • The reference resolver is an interface. Plain A1 references and named ranges are the library's own. A dotted name (T1.A1, M1.x) or a call on one (S1.fn()) goes to the program's resolver. A call into a script is the program's business: Snips makes it through the scripting plan's interfaces.
  • Numbers are doubles, as in Snips and Excel. BigInt and Complex are not cell values (question 5).

Questions for the user

Each comes with a recommendation and the reason for it.

1A library of its own, or part of the standard library?

  • A library of its own (import Formula), carried in ww.exe as Jade is: the standard library stays the language's core, and a built program that does not use formulas carries none of it.
  • In the standard library: always there, with no import needed; but a spreadsheet engine is a domain library, as windows are.

Recommended: a library of its own, named Formula.

Decided2026-11-19, the user ("do as Recommended for the formula plan"): a library of its own, import Formula, carried in ww.exe as Jade is.

2Whose formula language: Snips' exactly, or Excel's?

  • Snips' exactly: every Snips document works out the same once Snips moves to ww. That includes % as modulo, juxtaposition, or/and/not as words, [..] arrays, dotted paths and the hint forms.
  • Excel's: % as a percent, {..} arrays, Sheet!A1, AND() as a function only. Familiar to more people, but Snips' documents would change their answers.
  • Both, chosen per workbook: twice the language to test.

Recommended: Snips' exactly, plus exponent notation in formulas (1e3, which today reads as 1 times e3), which only adds. The Snips session decides whether 1e3 may change meaning in its documents.

Decided2026-11-19, the user (as recommended): Snips' language exactly, plus exponent notation in formulas; the Snips session decides whether 1e3 may change meaning in its documents.

3Recalculation: everything each time, or what changed?

  • Everything, as Snips does: simple and already right; costs the whole book at every edit.
  • What changed: a dependency graph and marking. A game updating a stat each frame, or a large Jade table, needs it. A random-edit test (part 3's gate) keeps it honest against working out everything.

Recommended: what changed, with "everything" kept as a check and an option.

Decided2026-11-19, the user (as recommended): what changed, through a dependency graph, with "everything" kept as a check and an option.

4IF and its kind: both branches worked out, or only the one taken?

  • Both, as Snips does: the same answers as now. But a branch never taken can still give a #CIRC!, slow a sheet, or call a script for nothing.
  • Only the one taken (IF IFS IFERROR IFNA CHOOSE, and and/or): as Excel does. Answers differ only where the branch not taken was a cycle, or called something that matters.

Recommended: only the one taken.

Decided2026-11-19, the user (as recommended): only the branch taken, for IF IFS IFERROR IFNA CHOOSE and and/or.

5Numbers in cells: doubles only?

  • Doubles, as Snips and Excel: every function is defined on them, and the tests compare against Snips.
  • BigInt and Complex too: exact factorials and complex results in cells, but every function would need to say what it does with them.

Recommended: doubles. A program that wants others can add them through Other and its own functions.

Decided2026-11-19, the user (as recommended): doubles; other kinds through Other and a program's own functions.

6When?

  • After the scripting plan, before the emitter: part 5 needs the scripting plan's interfaces for calls into scripts, and Snips' move to ww needs both.
  • After the emitter and the image work: the order agreed so far (the scripting plan, then the emitter, then PNG and WebP) stays as it is.

Recommended: after the scripting plan, before the emitter. Both are Snips' path to ww, and the engine is pure WinterWolf, which the emitter will later make faster.

Decided2026-11-19, the user (as recommended): after the scripting plan, before the emitter.
